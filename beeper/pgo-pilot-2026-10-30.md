# Same-source PGO pilot: higher median throughput, mixed H2 cycle results

Measured **30 October 2026**; published **31 October 2026**.

This pilot compares the corrected Candidate C runtime with and without profile-guided optimization (PGO). Across-arm median throughput is higher in all ten static-file cells (+4.61% to +49.93%), while measured server-process CPU per response is lower (−4.45% to −32.81%). Eight cells have a positive throughput change in every ABBA cycle. The two 32 KiB H2 cells change direction between cycles; H2c also has a **9.56% worse median arm p99**. These results support a workload-specific PGO benefit, not universal superiority or total-server CPU savings.

## Matched comparison

Both binaries use the same frozen source, features (`beeper-h2-serve`, `beeper-observer`, `quic-bpf`), native CPU target, frame pointers, optimization level 3, thin LTO and one codegen unit. The PGO build adds the collected profile; the control has no PGO. The [build receipts and frozen input manifest](../docs/evidence/pgo-c6ac-20261030/pgo-inputs.json) record the inputs; separate [control](../docs/evidence/pgo-c6ac-20261030/build-control.json) and [PGO](../docs/evidence/pgo-c6ac-20261030/build-use.json) receipts record the build settings.

- PGO candidate SHA256: `0ca04dcb8d3b9d07e02ac19658546d7882d6f2719c6937be2f259ca65eef83c5`.

H1/H2 kernel serving is off for both binaries, with zero observed kernel-serving successes. Both H3 arms use the accelerated on-core engine, GSO limit 20 and send batch 1. Both arms enable and warm the static fixture's cache path and finished-response memo; the page-cache response-memo setting also matches, but this pilot has no separate page-cache fixture. There is **no release comparison in this pilot**; the release artifact recorded in the provenance is not a measured arm here.

For 32 KiB H2c, the +7.66% median throughput change conceals cycle deltas of +68.26%, +3.29% and −10.95%; process CPU rises 17.88% in cycle 3. Its p99 improves 77.58% in cycle 1, then worsens 12.60% and 90.01%. This is not a consistent win. The 32 KiB H2 TLS median throughput gain (+4.61%) also includes a negative first cycle (−0.44%). Lower median p99 in 1 KiB H1 TLS, 1 KiB H2c and 32 KiB H2 TLS does not remove their opposite-sign latency cycles.

H3 throughput medians rise 21.56% at 1 KiB and 19.51% at 32 KiB, with positive cycle centers at both sizes. Those are PGO results with the same accelerated H3 engine on both sides; they are not evidence of in-kernel QUIC processing.

## Measurement scope and limits

The complete pilot contains **10 cells, 120 arms, 12,000,000 measured responses and 600,000 warm-up responses**. Each arm has 100,000 measured requests after 5,000 warm-up requests. Measurements run on Linux/WSL2 on SINGULARITY using literal `127.0.0.2` for both the server destination and client source bind: true Linux loopback, without a public origin or CDN. One server worker is pinned to CPU 8; six client threads use six physical cores (`0,2,4,6,12,14`). There are 32 connections and, for H2/H3, four streams per connection; H1 uses one request stream per connection.

- **RPS and p99** cover measured requests only. These are saturation/completion measurements; no scheduled offered rate is configured, so the p99 values do not describe latency at matched offered load.
- **Server-process CPU** is user plus system CPU for the observed server/descendant tree over the whole client span, including handshake, warm-up and teardown, divided by 105,000 responses per arm. It excludes kernel/IRQ work charged elsewhere and is not total-server CPU.
- **PMU instructions** cover server user mode only over that whole span, with the same 105,000-response denominator. They exclude kernel, IRQ and softirq work. Lower instruction counts do not establish total CPU savings.
- Repeated arms and ABBA order expose substantial drift in some cells. A positive across-arm median or cycle center does not imply that every individual PGO arm beat every control arm. This pilot covers warm static-file fixtures on one topology, not page-cache, dynamic-application or production-wide qualification.
